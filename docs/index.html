YOUR SELECTED EXPERIMENT

Digital RTL
simulation.

The testbench checks a SystemVerilog multiply-and-accumulate circuit over 100 million clock cycles per test. Verilator turns the circuit into a compiled simulator. Every test checks its own answer.

One worker executes all eight tests. Two workers split four each across separate nodes. Setup, compilation and warm-up are excluded. This synthetic digital RTL demo does not measure a full chip, analog SPICE or full-node throughput.

01
INFRASTRUCTURE

Deploy two E6 workers

Launch the Terraform package in OCI Resource Manager. Select your region, compartment, availability domain and a currently supported full Kubernetes version. The stack chooses a compatible Oracle Linux OKE image.

Deploy to Oracle Cloud ↗Download stack ZIP ↓

The deploy button activates when this page is published with its GitHub release. For a local preview, upload the stack ZIP through Resource Manager.

Before you apply

The defaults provision 32 OCPUs and 256 GB RAM across two nodes, plus networking and boot volumes. Normal OCI charges apply until you destroy the stack. Run Plan first: expect 12 resources to add for a new stack.

Which public IP should I enter?

From the client that will run kubectl, obtain its current egress IPv4 address. Add /32 to that address in the trusted CIDR field. For private access, connect Cloud Shell to the new worker subnet after provisioning.

curl -4 -fsS --connect-timeout 5 --max-time 10 https://api.ipify.org; echo
02
CLUSTER ACCESS

Connect from Cloud Shell

Wait for both workers to become Ready. Run the create_kubeconfig command shown in the stack outputs, then check your nodes.

export KUBECONFIG="$HOME/.kube/eda-e6-demo-config"
kubectl --request-timeout=10s get nodes -o wide \
  -L compute-family,node.kubernetes.io/instance-type

Expect two Ready VM.Standard.E6.Flex nodes. Cloud Shell connectivity depends on its selected network and your API security rule.

Connection timed out?

Confirm the endpoint matches your new cluster, your current egress IP matches the trusted CIDR, and the API subnet permits TCP 6443. For a private connection, attach Cloud Shell to the worker subnet from cloud_shell_private_network and generate kubeconfig with --kube-endpoint PRIVATE_ENDPOINT.

03
MEASUREMENT

Prepare, then press run

Download the benchmark ZIP and upload it to Cloud Shell. The preparation command installs the selected tools, compiles the circuit and checks correctness inside both pods.

unzip -o ~/oke-e6-benchmark.zip -d ~/
cd ~/e6-oke-demo
python3 tools/demo.py prepare --demo rtl
python3 tools/demo.py run --demo rtl
Install + prepare→Warm-up→6 measured batches

The controller runs in the background. A terminal disconnect does not restart it. Check progress after reconnecting; do not start overlapping measurements.

cd ~/e6-oke-demo
python3 tools/demo.py status
# When the run reports complete:
python3 tools/demo.py export

The RTL reference run took about 18 minutes, excluding preparation. Runtime varies. Worker pods have a four-hour deadline from creation; complete the measurement within that period.

How to interpret the numbers

Medians use three repeats per worker count. Speedup is one-worker median divided by two-worker median. Parallel efficiency is speedup divided by two. Two workers parallelize independent simulations; they do not make one simulation multithreaded.

This workload is small and CPU-focused. Each pod runs one single-threaded digital circuit simulation, capped at two logical CPUs and 4 GiB. It does not saturate each 16-OCPU node. Shape capacity, noisy neighbours, clock synchronization and software changes can affect observations. Validate your production tools and designs separately.

05
FINISH

Keep the evidence. Release the lab.

Export the archive and JSON before cleanup. Raw archives can contain infrastructure metadata; keep them private unless you intend to share them.

cd ~/e6-oke-demo
python3 tools/demo.py cleanup --demo rtl

This removes the demo worker Job and its input ConfigMap. To stop infrastructure charges, detach any Cloud Shell private-network attachment and run Destroy on the Resource Manager stack. Delete the stack record after the destroy succeeds.
